Coverage

What it does, and what it doesn't.

The honest version. Three of these are integrations into systems I haven't seen yet, and one is a dashboard nobody has asked for.

✓
WhatsApp agent: lead qualification and conversations
Meta Cloud API direct — webhook signature verification, interactive replies, four languages. Five qualification signals, graded with the reason. Conversations persisted as the model's memory and the audit trail.
✓
Meta Marketing API: campaigns, budget rules, creative tests, reporting
All four. Objects are created paused with no override, budgets are integers in minor units, and the budget rules evaluate as a pure function then apply as a dry run by default.
✓
Pixel / Conversions API tracking
Server-side events with PII normalised and SHA-256'd before sending, and an event id on every one so the pixel and the server deduplicate. Without that, cost per lead reads at half its real value.
✓
Cost control for LLM usage
Every call metered, attributed to the conversation that caused it. Three ceilings — per conversation per day, and per month — checked before the call. Going over hands the customer to a human rather than erroring.
✓
Logging and error handling
Writes to the ads API are logged before they are sent, redacted, so "did we do that?" always has an answer. A model that fails, misbehaves or goes over budget degrades to a handover — never to a number.
✓
Documentation: architecture, credentials, runbooks
Written as the work was done rather than afterwards. Every prompt is a file, every guarantee has a test naming the failure it prevents.
~
Follow-ups
Agent-side is live: unclaimed hot leads are chased after two hours, and a summary goes out at six. Customer-side reminders need WhatsApp templates approved against the brokerage's own number, which cannot happen before that number is connected.
~
Connect the stack: webhooks, REST APIs, event tracking
Webhooks in, Graph API out, conversion events back. The web platform and analytics ends are standard once there is something to point them at.
✗
CRM write-back
The graded lead is produced and served over an endpoint; nothing pushes it into a CRM yet. That is one function once I can see which CRM and what its lead object looks like.
✗
Monitoring beyond health checks
There is a health endpoint, a spend endpoint and a lead endpoint. No metrics pipeline and no alerting — worth adding when somebody other than me is on call.
✗
Product analytics, and Lead Ads form ingestion
No PostHog, and the leadgen webhook that would drop a Meta form submission straight into the agent's queue is not built.
✓ built and running ~ partly, and the rest is blocked on access ✗ not built
The two refusals

A chatbot that is usually right is no use here.

A buyer repeats your number to their bank. One invented figure is the brokerage's problem, not the model's — so the model is never the source of one.

It cannot invent a price

Every figure is read from the brokerage's own inventory file. An outbound guard holds the set of numbers those facts support, and a reply carrying anything else never leaves the process — it becomes a handover instead.

model wrote
"around AED 1,250,000, you'll see 9% yield"
customer received
"Let me have an agent confirm the exact figures and call you."

It gives no investment advice

Yield, appreciation, whether an area is going up, whether to buy — always a person. Checked before the price lookup, so an ROI question hiding inside a price question still reaches a human. That is RERA exposure, not politeness.

asked
"what's the ROI on a 2 bed in JVC and how much is it?"
routed
handover · reason: advice
What the sales floor gets

Five signals, read out of whatever the buyer volunteers. Asking again for something they just said is the fastest way to lose a chat, so one message can fill all five. A grade nobody can predict is one the floor stops trusting, so every grade carries why.

Under it

Built so the dangerous things are impossible.

campaigns
Nothing is created active. Campaigns, ad sets and ads are written PAUSED with no override; activating is a separate call that logs a warning.
budgets
Minor units, checked. A float raises TypeError — 50.0 means AED 50 to a person and AED 0.50 to Meta.
budget rules
Deciding is separate from doing. Evaluation is a pure function; applying defaults to a dry run, needs a minimum sample before forming an opinion, and moves a budget by one bounded step at most.
conversions
Personal data is SHA-256'd after normalising, with no flag to skip it, and every event carries an id so the pixel and the server deduplicate. Without that, cost per lead reads at half its real value.
retries
Selective. Meta answers a rate limit and your own malformed request with the same HTTP 400, so only the documented transient codes are retried.
